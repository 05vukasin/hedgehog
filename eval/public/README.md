# Public benchmark (model-free)

What hedgehog itself gives an agent on public spreadsheet QA and table-structure benchmarks, measured
without any LLM: no API calls, no model in the loop, same numbers on every run. Each metric has a naive
baseline beside it, run the same way, so the numbers mean something:

- **pandas**: `pd.read_excel(path, sheet_name=None, header=0)`, what a plain pandas tool hands an agent;
- **MarkItDown** 0.1.3: the whole workbook as markdown, what a "dump the file into the prompt" tool costs;
- **flood fill**: hedgehog's `baseline` analyzer (8-connected regions) for table detection.

Results: [RESULTS.md](RESULTS.md) (generated by `score.py`; per-dataset JSON in `results/`).

| **TableSense** (Dong et al., AAAI 2019) | annotations from [github.com/microsoft/TableSense](https://github.com/microsoft/TableSense); VEnron2 / VEUSES / VFUSE files (SpreadCluster, figshare, CC0) | O-UDA 1.0 (annotations) | yes, already in `testdata/irregular/` (no new download) | A (tables only) |

Not used here (a later, LLM phase): **SpreadsheetBench** (NeurIPS 2024 D&B; github.com/RUCKBReasoning/SpreadsheetBench,
CC BY-SA 4.0; `data/*.tar.gz` with 912 / verified-400 tasks and their xlsx, downloadable without an account) and
**SheetBench** (SheetBrain, arXiv 2510.19247; no official release found, only third-party "SheetBench-50"
uploads on Hugging Face, which are not the paper's data). Both are manipulation/answer tasks that need a model
to run. Koci et al.'s SAUS / CIUS / DeEx are already scored by `hedgehog benchmark --corpora strudel`.

Data never enters git: everything lives under `$HEDGEHOG_DATA/public/<name>/` (default `../testdata/public/`),
outside the repository. Only scripts, checksums and aggregate results are committed. Downloaded files are
untrusted: they are parsed, never executed; Python that reads them runs with `-I`; third-party parsers
(pandas, openpyxl, MarkItDown) run in bubblewrap (no network, no home folder, empty environment, a 3 GB
address-space cap), with the pinned venvs of `eval/agents/swap/setup.sh`.

## Reproduce

```sh
S=../scripts/run_capped.sh; L=../scratch-archive/public-bench/logs     # heavy steps under the memory cap
export SWAP_DIR=../scratch-archive/public-bench/swap
eval/agents/swap/setup.sh                                  # pinned pandas / MarkItDown venvs (once)
python3 -I eval/public/fetch_mimotable.py                  # downloads, verifies checksums/*.sha256
python3 -I eval/public/fetch_realhitbench.py
python3 -I eval/public/fetch_hitab.py
python3 -I eval/public/convert_mimotable.py                # -> <data>/public/<name>/items.jsonl
python3 -I eval/public/convert_realhitbench.py
$S 3G $L/conv.log python3 -I eval/public/convert_hitab.py   # trimmed workbooks (sandboxed), labels, items
python3 -I eval/public/convert_tablesense.py
for d in mimotable realhitbench hitab; do
  $S 3G $L/hh.log python3 -I eval/public/run_hedgehog.py $d --workers 2        # resumable
  $S 3G $L/bl.log env SWAP_DIR=$SWAP_DIR python3 -I eval/public/run_baselines.py $d
done
$S 3G $L/a.log python3 -I eval/public/run_structure.py --bin target/release/hedgehog
$S 3G $L/score.log $SWAP_DIR/venv-markitdown/bin/python -I eval/public/score.py   # tiktoken for o200k tokens
```

The fetch scripts are idempotent (`--record` pins the checksum of a file seen for the first time).
`run_hedgehog.py` uses `$HEDGEHOG_BIN` or `target-master/release/hedgehog`; the results in RESULTS.md come from
the release build of branch `fix-public` (baseline in the summary: master `2bd5e4e`). `run_structure.py` needs a build with the `public:` corpora.
Tool outputs go to `$HH_PUBLIC_WORK` (default `../scratch-archive/public-bench/`). Runtime on a laptop:
about a minute per dataset for hedgehog, a few minutes for the baselines, two minutes for scoring.

`make quick` runs a 14-table HiTab slice of metric B (`quick.py`, < 1 s plus the quick build; stored counts in
`quick.tsv`), skipped when the HiTab data is not on disk.

## Metrics

All string comparisons use one normalisation (`common.norm_text`): NFKC, case-folded, accents removed,
every run of non-alphanumerics → one space. Numbers (`common.parse_number`) read US and European grouping,
`(500)`, `%`; two numbers match when equal, or equal after rounding to the decimals the answer shows (only
when it shows decimals); a percent answer also matches its fraction (hedgehog stores 15 % as 0.15).

### A. Structure (where labels exist)

`hedgehog benchmark` with a corpus adapter (`--corpora public:<name>` reads `<data>/public/<name>/labels.tsv`
and the optional `tables.tsv`; `core/src/eval/labelled.rs`), no new scorer: cell-role accuracy (coarse roles),
table-detection P/R/F1 at IoU 0.5 / 0.8 / 1.0 and header-rows-exact.

- **HiTab**: the gold table is HiTab's table matrix, placed on the trimmed sheet with the offset its samples'
  `reference_cells_map` gives (and kept only when ≥ 80 % of its texts equal the sheet's cells there: 1,519 of
  1,578 tables). Rows above it are titles; its header rows are the top tree's depth plus unit-only rows right
  below (e.g. `percent`). HiTab's own `top_header_rows_num` is one more than its tree in almost every table
  (an NSF table with one header row says 2), so it is not used; this was decided after a first run scored
  42 % header-rows-exact against it, and checked by hand on NSF and StatCan tables. Left-header cells are data
  (group header when the rest of the row is empty), the body is data. Footnotes are not labelled.
- **TableSense**: table ranges only (no roles). The annotators converted `.xls` to `.xlsx`; the local copies
  are the `.xls` originals.

### B. Value–label linking (HiTab)

For each lookup question (aggregation `none`, one `[ANSWER]` data cell; 4,446), the answer cell's source
address is located in hedgehog's normalized output (the table on that sheet with `_src_row` = the row and a
column whose `source_column` is the column), and in pandas (DataFrame row via the sheet's row layout, column
by position). Then:

- **found**: the source cell is a cell of some table;
- **number stored = source**: the stored value is a number equal to the source cell's value (text that looks
  like a number does not count: StatCan sheets store their numbers as text, which pandas keeps);
- **column header exact**: the gold top-header path (HiTab's top tree, e.g. `eastern ontario › french-language
  workers`) appears as whole `" / "` segments, in order, in the column name (extra segments such as a unit are
  allowed); **lenient**: every path element is a substring of the column name, spaces ignored;
- **row labels exact**: every element of the gold left-header path (left tree, header-row nodes dropped) equals
  one of the row's text values (label columns, group column); **lenient**: substrings of the row's labels
  joined; **leaf**: only the innermost label;
- **both**: column and row exact (lenient).

For pandas, "row labels" are all non-numeric cells of the row, which favours it (numbers stored as text count).

### C. Answer reachability

Per QA item with a value or short-list answer, split into **atoms**: HiTab's answer list; RealHiTBench's
`ProcessedAnswer` split on `, ` / `;`; MiMoTable's free-text answers reduced to their quoted phrases and the
numbers the question does not contain (`common.atoms_from_narrative`; noisy by nature: an annotator's
narrative may quote a column name or an intermediate number). An item is **verbatim** when every atom equals
a cell of its source file (raw cells, `hedgehog cells`); then:

- **(i) catalog**: every atom appears in hedgehog's `open_file` text (numbers among its numbers, phrases at
  word boundaries); for comparison, in MarkItDown's full markdown;
- **(ii) cell**: every atom is a cell of one normalized table (hedgehog CSVs / pandas DataFrames), or a column
  name / title (narrative answers quote column names; "which year" answers are year columns);
  **loose**: plus a row label or the column header shares a content word with the question;
  **strict**: plus both do (for a text atom: the column header). Content words: Latin words of 3+ letters
  minus stop words, numbers, CJK character bigrams.

Items whose atoms are not all cells **need a query** (a sum, a comparison, a count …). For them: are the
operand columns clean numeric columns (numeric dtype, and no row whose label reads like a total counted as a
data row: hedgehog marks them in `_row_type`; pandas has no such column)? HiTab gives the operand cells
(`[ANSWER]` cells of non-`none` aggregations), so that check is exact; for MiMoTable and RealHiTBench the
operand columns are *guessed* as the numeric columns whose header shares a word with the question (a
heuristic; it says whether such columns exist and are clean, not whether they are the right ones).

Grouping uses each benchmark's own labels: MiMoTable `meta_operation_list` (`lookup` = only Lookup;
`needs_query` = Calculate / Compare; `not_measured` = any Reasoning, Visualize, Edit), language and table
type; RealHiTBench `QuestionType` / `SubQType` (Data Analysis and Visualization are free-text or chart answers:
not measured), and `QA_long` (tables the authors set aside as too long for a prompt) separately; HiTab
`lookup` / `computed` / `header_answer`.

**Not measured**: whether an agent would actually find or compute the answer (that needs a model), free-text
analyses, charts, edits, and the correctness of a query's result. "In the catalog" is a strong condition: a
catalog is a summary (columns, value ranges, sample rows), not the data; the rest is one `query` away, which
(ii) measures.

### D. Cost

Per file: `open_file` catalog characters and tokens (o200k via tiktoken, as `eval/info/score.py`; characters / 4
when tiktoken is missing, the report says which), wall time of the `hedgehog mcp` process for one `open_file`
(cold: `HEDGEHOG_CACHE=0`), peak RSS of exactly that process (`maxrss.c`: a tiny launcher so the parent's memory
is not counted), and failures by error class. MarkItDown: markdown characters and tokens, convert time, peak
RSS of the forked worker (includes the imported library). pandas: read time and peak RSS. Files over 200 MB
would be skipped (none here).

## Caveats

- HiTab files are the **trimmed** annotation workbooks: the annotators' block under each table (sentence,
  question, answer, formula) is cut, other sheets dropped, cached values kept (formulas become values); without
  the cut, answers would be in the file as text. openpyxl rewrote them, so styles are openpyxl's.
- The MiMoTable atoms come from narratives; numbers there are often intermediate values. The filter "atom is a
  cell of the file" removes most noise, but a verbatim item may still include a number that is not the answer.
- RealHiTBench's `QA_long` questions reference the same workbooks as other QA; "long tables" groups them only.
- pandas' row mapping needs the sheet's row layout (header = the sheet's first row, blank rows kept); when it
  cannot be confirmed the sheet's rows count as not found (none in HiTab).
