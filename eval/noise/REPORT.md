# Noise robustness report

Generated by `eval/noise` (`noise_eval`): 21 families × 5 intensities × 60 seeds = 6300 scenarios, each normalized with `--rules-only` and with the learned model (12600 runs, 33 s, 2.5 ms per normalize). Real clean tables mixed into the bases: plotly_datasets/tips.csv, fivethirtyeight/airline_safety.csv, fivethirtyeight/bad_drivers.csv, northwind/products.csv, plotly_datasets/gapminder_five_year.csv, data_gov_rs/rzs_zaposleni_cyr.csv, vega_datasets/seattle_weather.csv.

**Crashes / panics: 0.**

## How to run

```sh
export CARGO_TARGET_DIR=$PWD/target-noise HEDGEHOG_DATA=/path/to/testdata
eval/noise/sweep.sh 60        # capped jobs of one family x 5 intensities x <= 40 seeds (<= 200 workbooks each), then this report
$CARGO_TARGET_DIR/release/noise_eval --repro subtotals 0.75 3   # one scenario: the sheet, both paths, every invariant
```

A scenario **passes** when every applicable invariant holds for every cell it covers. Intensity 0 is the clean table (title, header, body); 1 is the hardest variant of the family. Generated sheets go to `--work` (failing examples are copied to `<work>/failures/`), never into the repository.

Invariants:

- `placed`: every data value is in exactly one table cell (not lost, not duplicated, not on Totals/Notes)
- `value`: the value is typed and equal to the original (missing tokens → empty; scale applied or not)
- `labels`: the row's key labels (row texts, group column, block title) stay with the value
- `header`: the column name carries the header path (parents + child, normalized match)
- `tables`: no output table mixes two source tables; a source table is not split (unless it is made of blocks)
- `notes_out`: titles, notes, unit rows, separators, comments and group label cells are not table data
- `totals_found`: every inserted sum total is on Totals
- `totals_ok`: every inserted sum total that was found verifies (status ok)
- `totals_out`: total, average and of-which rows are not table data
- `nonsum`: average / of-which rows on Totals are not reported as mismatches
- `scale`: a stated scale is applied to the values or kept in the column name / unit / title / notes
- crash: normalize (or the reader) panicked; counted as a failure of every invariant.

  as `1948 | 2043 | 338` taken as a new header).

## Audit of the existing generator (`tools/noise`, untouched)

What it does: 51 operators in four stages (A values 18, B structure 17, C layout 9, D presentation
7), each a per-table / per-sheet Bernoulli draw with a profile probability (`enron_like` 50%,
`gov_stats` 20%, `eu_locale` 20%, `clean_ish` 10%), calibrated to DECO sheet statistics; sources
are ≤ 4 chunks × 300 rows of the clean tables. It writes full cell-role ground truth and is the
`synthetic` training corpus of the shipped model.

Parameters are probabilities, not intensities: an operator is on or off, so there is no curve,
and its habits are fixed. Patterns it does not produce (or produces in one form only), found by
the new families and the hints in docs/evaluation.md and BACKLOG.md:

| Not produced by `tools/noise` | New family | Result |
|---|---|---|
| "of which / davon" breakdown rows | `of_which` | 0% → 100% |
| average / mean / median rows (only sums, wrong sums, sums as values) | `average_rows` | 22% → 100% |
| subtotals *above* their group, grand total at the top | `subtotals` | 27% → 100% |
| registers with total words at the *start* of free text (B1 found it inside) | `long_register` | 0% → 100% |
| `:` and `c` symbols (Eurostat / ONS); free text like `<5` in numeric columns | `locale`, `mixed_types` | 42%, 5% |
| footnote marks `(r)`, `e`, superscripts at higher rates; legend directly under the table | `footnotes` | 2% |
| rare / foreign / misspelled total labels (cs, pl, da, fi, hu, ru, typos, ∑) | `total_labels` | 55% → 100% |
| separator rows (`-----`, `=====`) and `|` columns | `separators` | 37% |
| comments in the column right of a table, notes inside the body | `notes` | 32% |
| parent headers written once or centred without a merge | `multirow_header` | 38% |
| `YYYY-MM` / `Jan 2010` period headers, 60-column grids, a year row over month names | `wide_periods` | 68% |
| label columns repeated per year block | `label_blocks` | 100% (model) |
| two-language headers, Latin/Cyrillic mixed in one table | `multilingual` | 100% |
| periods across with a year row over quarters | `transposed` | 100% |

The DECO / European-sample error analysis points the same way: totals (51.7 / 29.7 F1) and group
headers are the weak roles on real data, and the families that drop hardest here are total-like
rows. The old generator's corpus scores 93–98% for the model partly because it never asks these
questions.

## Training on the new families (write-up only; nothing was retrained)

Most failures above are **not** row-model problems: footnote marks and `:` in numbers, the 90% typing
rule, total-label vocabulary, average / of-which rows and scale handling live in the value parsers,
the totals module and `extract`. Retraining can only help the row-role failures: a lone last row
or a footnoted / text-only data row taken as a total or header (`spacers`, `footnotes`,
`mixed_types`, `labels_once`), separator, note and comment rows inside the table (`separators`,
`notes`), centred / written-once parent headers (`multirow_header`), and side-by-side tables merged
into one. Fix the rule-side items first; then a retrain is worth testing.

Protocol, so that the new data cannot buy synthetic points with real-data losses:

1. **Labels.** Emit a role for every written cell from the truth the harness already keeps
   (data, header and parent header cells, total for sum rows, title, note for notes / legends /
   comments, other for separators, group_header for group label rows). Decide the two contested
   conventions first and write them down: an of-which row and an average row are `total` (not
   additive, but not data either), and a centred parent header is `header` over its whole span.
   Export with `hedgehog features --level row` like the other corpora (`noise2` corpus).
2. **Disjoint seeds and bases.** Training workbooks use seeds ≥ 10 000 and only generated bases
   plus real clean tables *not* in `base::REAL_FILES`; this report keeps seeds 0–999 and its real
   tables, so the robustness curves stay an honest held-out measure.
3. **Weight sweep.** noise2 rows at 0 / 5 / 10 / 20 % of the training rows (style dropout 0.3 as
   now). More is not better: the shipped model's strength is the real corpora.
4. **Seed-mean.** Every configuration trained with 3–5 XGBoost seeds; compare means and the worst
   seed. A difference smaller than the seed spread (±1 point per file on the European sample, up
   to ±5 on small roles, see learned-model.md) is noise, not an effect.
5. **Gates, in this order:**
   - leave-one-*real*-corpus-out (DECO, StatSheets, Strudel, synthetic v0) with and without noise2
     in the training set: the held-out real corpus must not get worse on the seed mean;
   - leave-one-*family*-out inside noise2 (train on 20 families, test the 21st): measures whether
     the model learns the patterns or memorizes this generator's habits — the user's concern. A
     family that only improves when it is in training is overfitting the generator;
   - the release rule on the test splits (no corpus worse, the European sample never worse), and
     the agent eval (worst run) unchanged;
   - then the robustness curves on held-out seeds as the gain to report.
6. **Cross-generator check.** Also test the retrained model on `tools/noise` v0 (old generator) and
   the old-generator-trained model on noise2: if each only improves on its own generator, the gain
   is generator-specific.

## Limits of this harness

- One sheet per workbook, one value convention per table; no hidden rows, styles, charts, or
  cross-sheet formulas (the old generator has styles and hidden rows).
- Truth is about content, not cell roles: a correct output that names a column differently is
  checked by a normalized substring match (`header`, `labels`), which can pass a near miss.
- Some invariants encode a choice: `totals_out` / `nonsum` treat average and of-which rows as
  not-data, and `tables` treats side-by-side tables with the same row count as separate unless
  they share labels. `value` is strict: a number left as text fails even when it is kept.
- `:` as a missing token and EU integers like `4.405` (= 4405) in a column of typed numbers are
  deliberate hard cases; the date convention always matches the number convention.
